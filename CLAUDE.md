# Правила выполнения лабораторных и практических работ

## Структура репозитория
- `inbox/` - сюда кладутся новые задания и образцы.
- `labs/<работа>/` - готовая работа: только отчёт `.docx` и код на Python (один файл или несколько модулей, если этого требует задание). Папки: `lab6`, `lab7`, `lab8`, `lab36`, `lab38_39`, `lab40_41`, `lab42_43`, `op09/pr1` ... `op09/pr4_5`.
- `tasks/` - исходные задания, перенесённые из `inbox/` после выполнения.
- `tools/make_docx.py` - генератор docx по образцу с рамкой; `tools/build/<работа>.py` - сборка отчёта: запускает код из `labs/<работа>/` и вставляет его реальный вывод.
- `lectures/`, `characteristics/` - лекции, презентации, характеристики.

## Как выполнять работу
1. Прочитать задание в `inbox/`, определить вариант. Вариант = 13 по остатку: если вариантов N, берётся 13 mod N (из 6 получается 1, из 14 остаётся 13, из 16 остаётся 13).
2. Написать максимально простой код в `labs/<работа>/`. Код как у студента: короткие функции и классы, понятные имена, строки не длиннее 80 символов, без каких-либо комментариев и docstring, без тестовых фреймворков, типов, lambda и списковых выражений.
3. Сделать скриншоты кода в VS Code (`tools/build/screenshots.py`: VS Code установлен в `/usr/share/code`, нужен `Xvfb :98 -screen 0 1280x1000x24` и запущенный редактор с настройками из `tools/build/vscode-settings.json`). Написать `tools/build/<работа>.py` и собрать отчёт: код в отчёте вставляется скриншотами, а не текстом, вывод программы текстом. Результаты запусков реальные, цифры не выдумывать.
4. Проверить рамку на каждом листе: `soffice --headless --convert-to pdf файл.docx`, затем `pdftoppm -png` и посмотреть страницы.
5. Задание перенести из `inbox/` в `tasks/`, закоммитить и запушить.

## Оформление отчёта
- Формат `.docx` с рамкой и штампом на каждом листе (колонтитулы образца `inbox/LR1-2_KucherUD_31ISIP.docx`), поля 2 см, шрифт Times New Roman 14, интервал 1,5. Рамка нужна только в работах, в лекциях и презентациях её нет (`build(..., frame=False)`).
- Фамилия в штампе: работы 6-8 оставлены с фамилией из образца (Кучер У.Д.), 36-43 подписывает Лебедева С.К., практические по ОП.09 подписывает Нечаева В.В. Строка проверяющего пустая: `build(..., author="Фамилия И.О.", reviewer="")`.
- Структура: заголовок «Лабораторная работа №N» и тема, затем «Цель работы:», «Задание:», «Теоретическая часть», «Ход работы» с листингом кода и результатом запуска, «Вывод». Для практических по ОП.09 добавляются ответы на контрольные вопросы («Ответ: ...»).
- **Никаких списков и сворачиваемых заголовков.** Названия разделов делаются обычными жирными абзацами, а не стилями «Заголовок» (иначе в Word слева появляются стрелки сворачивания). Маркированные и нумерованные списки Word не использовать, перечисления писать предложениями. Допустимы таблицы и блоки кода.
- Каждая работа самостоятельна: в отчёте и коде не упоминать другие лабораторные и практические работы, даже если тема или код похожи. Модули, примеры и данные брать свои, внутри папки работы.
- Текст в академическом стиле, от первого лица в женском роде («я разобрала», «я составила») или безлично. Без пометок о том, что чего-то нет или что нужно уточнить у преподавателя. Без штампов нейросети: «важно отметить», «стоит подчеркнуть», пафосные итоги, перечисления по три, длинные тире в тексте (в подписях таблиц допустим дефис). Если в исходных данных чего-то не хватает, берётся разумное решение и подаётся как выполненная работа.

## Лекции и презентации
- Лекции в `lectures/`, без рамки, академический стиль, ключевые моменты выделены жирным.
- Презентации по умолчанию в `.pptx` (`lectures/build_presentation_*.js`, pptxgenjs; запуск: `NODE_PATH=<папка с node_modules> node скрипт.js файл.pptx`).
